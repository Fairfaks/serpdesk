# Задача: импорт запросов с историей позиций из других сервисов (RUSH Analytics, Топвизор, xlsx/csv)

## Проект (кратко)

SerpDesk — десктопный съёмщик позиций (Electron 37). main-процесс `main.js`,
`preload.js` (contextBridge → `window.api`), рендерер `renderer/app.js`, база на
sql.js `lib/db.js`. UI русский, тёмная тема. Node из Screaming Frog:
`export PATH="$HOME/.ScreamingFrogSEOSpider/node/5.1/node/bin:$PATH"`.
Запуск `npm start`, тесты `npm test`, сборка `npm run dist:mac` / `dist:win`.

## Что нужно

Дать возможность загрузить в проект список фраз **вместе с историческими позициями**
из выгрузки стороннего сервиса (в первую очередь RUSH Analytics), чтобы графики
(Динамика/Сравнение) сразу имели историю, а не начинались с нуля.

## Точный формат исходника (образец лежит в Downloads)

Файл-образец (реальный экспорт RUSH Analytics):
`/Users/Fairf/Downloads/businessmens_ru_History_Proverka_pozitsij_Yandeks_Moskva_Kompyyuter_xlsx_1784838100.xlsx`

Лист **«История позиций»**, строка 0 — заголовок:
```
Ключевое слово | Теги | Трафик | Частотность | 23.07.2026 | 14.07.2026 | 24.06.2026 | Целевой URL | Релевантный URL
```
Строки данных, пример:
```
франшиза дринкит |  |  | 170 | 9 | 7 | 5 |  | https://businessmens.ru/...
франшиза магнит  |  |  | 46  | 32 | 26 | 12 |  | https://businessmens.ru/...
```
То есть: столбцы-даты в формате `ДД.ММ.ГГГГ` (новые слева) содержат **позицию**
фразы на эту дату. Частотность — число. Теги — строка (может быть пусто). Целевой
URL и Релевантный URL — необязательные.

В файле ещё есть листы «История URLов» и «Сниппеты» — их импортировать НЕ нужно
(в MVP), берём только «История позиций». Но парсер должен опираться на имена
колонок, а не на их порядок (у Топвизора и при экспорте в CSV порядок/язык могут
отличаться).

### Минимально достаточный формат

Обязательны только **фраза + столбцы-даты с позициями**. То есть простейший
принимаемый файл:
```
запрос | 23.07.2026 | 14.07.2026 | 24.06.2026
франшиза магнит | 32 | 26 | 12
```
Всё остальное (Теги, Трафик, Частотность, Целевой/Релевантный URL) — необязательный
бонус: если столбцы есть — подтягиваем, если нет — молча пропускаем. Не требовать их.

### Две поисковые системы (важно)

RUSH (и Топвизор) выгружают **отдельный файл на каждую связку ПС + регион +
устройство** — это видно по имени образца: `...Yandeks_Moskva_Kompyyuter...`
(Яндекс, Москва, десктоп). В одном файле позиции только по ОДНОЙ поисковой системе.

Поэтому: **один импорт = один engine + device**, выбираются в диалоге импорта
(предзаполнить из текущих вкладок проекта; если в имени файла есть `yandex`/`google`,
`mobile`/`phone`/`desktop`/`komp` — предугадать). Чтобы загрузить и Яндекс, и Google,
пользователь импортирует два файла, в каждом указывая свою ПС. Не пытаться угадывать
две ПС из одного файла и не смешивать их — данные лягут в разные наборы прогонов
(`runs.engine`), и вкладки Яндекс/Google покажут каждую свою историю.

## Требования

### 1. Формат входа

Поддержать **.xlsx** и **.csv** (RUSH и Excel умеют оба). Для .xlsx добавь
зависимость SheetJS: `npm i xlsx` (парсинг в main-процессе). CSV парсить самим
(разделитель `,` или `;` — определить по первой строке; учитывать кавычки).

### 2. UI

В шапке проекта (рядом с «+ Запросы») или внутри модалки «+ Запросы» добавить
пункт **«Импорт истории…»**. По клику:
1. Диалог выбора файла (`dialog.showOpenDialog`, фильтр xlsx/csv) — хэндлер в main.
2. main парсит файл, определяет колонки и даты, возвращает в рендерер превью:
   сколько фраз, какие даты найдены, в какой поисковик/устройство лягут.
3. Модалка превью: показать найденные даты и поля-сопоставление; дать выбрать
   **поисковик** (Яндекс/Google) и **устройство** (десктоп/мобайл) — из файла это
   не всегда однозначно (в образце подсказка в имени файла: «Yandeks … Kompyyuter»,
   можно предзаполнить, но выбор оставить за пользователем; по умолчанию — текущие
   вкладки проекта). Кнопка «Импортировать».

### 3. Разбор и сопоставление колонок

- Заголовок — первая непустая строка. Сопоставлять по имени (trim, lower, без учёта
  регистра), с синонимами:
  - фраза: «ключевое слово», «фраза», «запрос», «keyword», «query» → иначе первый
    столбец;
  - теги: «теги», «tag», «tags»;
  - частотность: «частотность», «частота», «frequency», «volume», «ws»;
  - целевой URL: «целевой url», «target url»;
  - релевантный URL: «релевантный url», «url», «страница»;
  - **даты-позиции**: любой столбец, чей заголовок парсится как дата
    `ДД.ММ.ГГГГ` (а также `ДД.ММ.ГГ`, `ГГГГ-ММ-ДД` — на всякий случай).
- Значение позиции в ячейке даты: целое число → позиция; пусто → пропустить
  (нет данных за эту дату); `—`, `-`, `>100`, `100+`, `101`, `не найден`, `нет`
  → трактовать как «не в топе» = 0. Прочий мусор → пропустить.

### 4. Запись в базу

Схема (см. `lib/db.js`): `keywords(project_id, phrase, freq, tag, target_url,
created_at, UNIQUE(project_id,phrase))`; `runs(project_id, engine, device,
started_at, finished_at, status)`; `results(run_id, keyword_id, position, url,
error)`.

Алгоритм импорта в выбранный проект:
1. Для каждой строки — upsert фразы. **Нормализовать фразу так же, как при ручном
   добавлении** (`keywords:add` в `main.js`: trim + схлопнуть пробелы `\s+`→` `),
   чтобы одна и та же фраза из разных файлов и из живых проверок считалась одной
   записью, а не дублировалась. Если фразы нет — вставить (phrase, freq, tag,
   target_url, created_at=now); если есть — дозаполнить freq/tag/target_url только
   там, где пусто (не затирать существующее непустым). Сопоставление по
   `(project_id, phrase)` (UNIQUE).

Импорт СКЛАДЫВАЮЩИЙ (union): разные файлы в один проект дают объединение фраз и дат.
Где фразы не было в данном файле на данную дату — ячейка остаётся пустой (нет данных),
это нормально. Одинаковая фраза+дата из двух файлов → та ячейка перезаписывается
последним импортом (значения должны совпадать, если источник один). Существующие
живые проверки и другие импортированные даты НЕ трогаются.
2. Для каждой колонки-даты — получить-или-создать `run` для
   `(project_id, engine, device, date)`: искать существующий по
   `date(started_at)=дата`; если нет — вставить с
   `started_at = <дата>T12:00:00`, `status='done'`, `finished_at=<дата>T12:00:00`,
   выбранным engine и device.
3. Записать позицию: `INSERT OR REPLACE` в `results` по (run_id, keyword_id) со
   значением position (url можно взять из «Релевантный URL», если он один на строку;
   иначе null).
4. Всё — идемпотентно: повторный импорт того же файла не должен плодить дубликаты
   (за счёт reuse run по дате и REPLACE по (run_id, keyword_id)).
5. `db.flush()` в конце.

Импортированные даты должны корректно встроиться в общий таймлайн: `getGrid`
сортирует прогоны по `started_at`, поэтому исторические даты появятся слева от
текущих, и Динамика/Сравнение заработают по ним сразу.

### 5. Результат и ошибки

По завершении — тост: «Импортировано: N фраз, M дат, K значений». Если лист
«История позиций» не найден / не распознан ни один столбец-дата — понятная ошибка.
Большие файлы (тысячи строк) — не морозить UI: парсинг в main, вставки в
транзакции/пачкой, прогресс по желанию.

## Стиль и ограничения

- Держать стиль кода: русские комментарии, IPC через хелпер `h(name, fn)` в
  `registerIpc()`, методы в `contextBridge` + канал в whitelist `allowed`
  (`preload.js`), настройки строками '0'/'1'.
- Не ломать существующую логику проверки, автопроверку, автообновления, видео-финал.
- Кроссплатформенно (Mac/Windows).
- Поднять версию в `package.json`.
- `xlsx` (SheetJS) — единственная новая зависимость; добавить в `build.files` уже
  покрыто `node_modules/**`.

## Как проверить (обязательно)

1. `node --check main.js preload.js renderer/app.js`, `npm test` — чисто.
2. `npm start` → создать пустой проект → «Импорт истории…» → выбрать файл-образец
   выше → выбрать Яндекс/десктоп → импорт. Ожидание: 3 даты (24.06, 14.07, 23.07),
   у «франшиза магнит» позиции 12 / 26 / 32, частотность 46 подтянулась.
3. Открыть вид «Динамика» и «Сравнение» — работают по импортированным датам.
4. Повторный импорт того же файла — числа не задвоились (та же сетка).
5. `npm run dist:mac` собирается.

  канал прогресса в `allowed`.
