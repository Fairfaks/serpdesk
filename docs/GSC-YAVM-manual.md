# Мануал: как подключить Яндекс.Вебмастер, Google Search Console и Метрику

Что это даёт: по твоим же фразам рядом с «синтетической» позицией из XMLRiver появятся
**реальные показы, клики, CTR и средняя позиция** из статистики поисковиков по сайтам,
к которым у тебя есть доступ в GSC/ЯВМ. Подключения необязательны и работают независимо.

---

## Часть 1. Яндекс.Вебмастер (проще, начни с него)

Понадобится аккаунт Яндекса, под которым сайты подтверждены в Вебмастере.

### Шаг 1. Создать OAuth-приложение (один раз)

1. Открой https://oauth.yandex.ru → **Создать приложение**.
2. Название — любое (например `SerpDesk`).
3. Платформа: **Веб-сервисы**, Redirect URI — нажми «Подставить URL для отладки»
   (подставится `https://oauth.yandex.ru/verification_code`).
4. Доступы: раздел **Яндекс.Вебмастер** — отметь оба права:
   - `webmaster:hostinfo` — просмотр информации о сайтах;
   - `webmaster:verify` — список сайтов.
5. Сохрани. Скопируй **ClientID**.

### Шаг 2. Получить токен

Открой в браузере (подставь свой ClientID):

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>
```

Залогинься под аккаунтом, где лежат сайты → «Разрешить» → на экране появится **токен**.
Живёт он месяцами; протух — получаешь заново той же ссылкой.

### Шаг 3. Проверить, что работает

```bash
# свой user_id
curl -H "Authorization: OAuth <ТОКЕН>" https://api.webmaster.yandex.net/v4/user/

# список сайтов (host_id вида "https:site.ru:443")
curl -H "Authorization: OAuth <ТОКЕН>" https://api.webmaster.yandex.net/v4/user/<USER_ID>/hosts/

# топ поисковых запросов сайта с показами/кликами/позициями
curl -H "Authorization: OAuth <ТОКЕН>" "https://api.webmaster.yandex.net/v4/user/<USER_ID>/hosts/<HOST_ID>/search-queries/popular/?order_by=TOTAL_SHOWS&query_indicator=TOTAL_SHOWS&query_indicator=TOTAL_CLICKS&query_indicator=AVG_SHOW_POSITION&query_indicator=AVG_CLICK_POSITION&limit=500"
```

Параметры: `date_from`/`date_to` — период (по умолчанию последняя неделя),
`offset`+`limit` — пагинация по 500.

### Ограничение ЯВМ (важно)

API отдаёт **ТОП-3000 запросов сайта по показам**, произвольную фразу спросить нельзя.
То есть свои фразы мы ищем в этом топе; если фраза не вошла в топ-3000 показов —
данных по ней в ЯВМ не будет. Для малотрафичных сеточных сайтов это основной случай,
для мани-сайтов с трафиком — данные будут.

## Часть 2. Google Search Console

Тут два пути:

- **Путь Б (вход через Google)** — если среди сайтов есть ЧУЖИЕ, где ты не владелец
  и не можешь приглашать пользователей: вход под твоим аккаунтом наследует все
  доступы, которые тебе выдали. В SerpDesk встроено кнопкой «Войти через Google».
- **Путь А (сервисный аккаунт)** — для своих сайтов: без браузерных входов и
  протуханий, но робота нужно пригласить в каждый ресурс (нужны права владельца).

Если выполнен вход через Google — SerpDesk использует его, JSON-ключ игнорируется.

### Путь А. Сервисный аккаунт (рекомендую)

1. Открой https://console.cloud.google.com → создай проект (имя любое).
2. **APIs & Services → Library** → найди **Google Search Console API** → **Enable**.
3. **IAM & Admin → Service Accounts** → **Create service account** (имя любое,
   роли не нужны) → создать.
4. Открой созданный аккаунт → вкладка **Keys** → **Add key → Create new key → JSON**.
   Скачается файл ключа — храни его как пароль.
5. Скопируй **email** сервисного аккаунта (вида `name@project.iam.gserviceaccount.com`).
6. Открой https://search.google.com/search-console → выбери ресурс →
   **Настройки → Пользователи и разрешения → Добавить пользователя** → вставь этот
   email, права **«Полный»** (для чтения хватит и «Ограниченный»).
   Повтори для каждого сайта, который хочешь цеплять.

Всё — приложение подписывает запросы этим JSON-ключом и ходит в API без браузера
и без протухающих refresh-токенов. Ключ работает, пока ты его не отзовёшь.

### Путь Б. Вход через Google (кнопка в SerpDesk)

Нужен OAuth-клиент типа **Desktop** в Google Cloud (годится уже существующий):

1. https://console.cloud.google.com → **Auth Platform → Clients**. Если Desktop-клиента
   нет — Create client → Desktop app. Скопируй **Client ID**
   (вида `…apps.googleusercontent.com`).
2. Client secret: если старый секрет неизвестен (Google больше не показывает
   созданные ранее), открой клиента → **Add secret** → скопируй новый (`GOCSPX-…`).
3. **Auth Platform → Audience**: если статус Testing — добавь свою почту в
   **Test users**. А лучше сразу нажми **Publish app** (статус In production) —
   иначе Google сбрасывает вход **каждые 7 дней**. При «непроверенном» приложении
   на входе будет предупреждение — жми Advanced → Continue, это нормально для
   личного инструмента.
4. В SerpDesk: ⚙ Настройки → вставь Client ID + Client secret → **«Войти через
   Google»** → в браузере выбери аккаунт, где лежат сайты, разреши доступ →
   вернись в приложение: статус «✓ вход выполнен».

Этот способ видит **все ресурсы твоего аккаунта GSC, включая чужие сайты**,
куда тебя добавили с любыми правами (Full/Restricted — читать статистику можно).

### Запрос данных

Эндпоинт: `POST https://www.googleapis.com/webmasters/v3/sites/<siteUrl>/searchAnalytics/query`
(siteUrl — URL-энкоженный `https://site.ru/` или `sc-domain:site.ru`).
Scope: `https://www.googleapis.com/auth/webmasters.readonly`.

Тело — период, размерности и фильтр **точно по своей фразе** (в отличие от ЯВМ,
GSC умеет отвечать по конкретному запросу):

```json
{
  "startDate": "2026-06-23",
  "endDate": "2026-07-21",
  "dimensions": ["query"],
  "dimensionFilterGroups": [{
    "filters": [{ "dimension": "query", "operator": "equals", "expression": "банкротство физических лиц москва" }]
  }],
  "rowLimit": 25
}
```

В ответе по каждой строке: `clicks`, `impressions`, `ctr`, `position`.
Быстро потрогать руками без кода можно в OAuth 2.0 Playground
(https://developers.google.com/oauthplayground): выбрать scope webmasters.readonly,
получить токен и слать curl с `Authorization: Bearer <token>`.

Нюансы GSC: данные с задержкой ~2 дня, история до 16 месяцев, позиции — средние
по реальным показам (могут отличаться от съёма «здесь и сейчас» — это нормально).

## Часть 3. Яндекс Метрика (необязательно)

Метрика дополняет данные поисковиков визитами, пользователями, отказами, глубиной,
временем на сайте и достижениями избранных целей по самой поисковой фразе. Трафик
страницы не распределяется между запросами.

1. Открой https://oauth.yandex.ru/client/new и создай приложение SerpDesk.
2. В доступах выбери чтение статистики Яндекс Метрики (`metrika:read`). Если то же
   приложение уже используется для Вебмастера, можно добавить оба типа прав.
3. Открой ссылку, подставив ClientID:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>
```

4. Разреши доступ и скопируй полученный токен в поле «Токен Яндекс Метрики».
5. Обычно SerpDesk сам находит счётчик по домену. Если не нашёл, открой настройки
   проекта и укажи числовой ID счётчика вручную.

Важно: Метрика скрывает часть низкочастотных поисковых фраз из-за порога раскрытия.
Пустая ячейка в SerpDesk поэтому означает «данные по фразе не вернулись», а не ноль.

## Часть 4. Куда вводить в SerpDesk

1. **⚙ Настройки** (внизу слева) → секция «Реальная статистика поисковиков»:
   - **Токен Яндекс.Вебмастера** — вставить токен из Части 1;
   - **Токен Яндекс Метрики** — вставить токен из Части 3, только если нужна Метрика;
   - **Ключ Google** — кнопка «Выбрать…» → указать скачанный JSON сервисного
     аккаунта из Части 2 (файл лежит на диске, в базу пишется только путь);
   - «Проверить подключение» покажет, сколько сайтов/ресурсов доступно.
2. В проекте нажать **«⟳ Данные»** — приложение обновит только те источники, которые
   подключены. Сайты и счётчик подбираются по домену, период задаётся в проекте.
3. В сетке появятся колонки **Показы · Клики · Поз.ПС** (CTR — в тултипе ячейки):
   на вкладке Яндекс — данные Вебмастера, на вкладке Google — данные GSC.
   Колонки сортируются кликом, выгружаются в CSV.
4. Если подключена Метрика и она вернула фразы, появятся колонки **Визиты · Люди ·
   Отказы · Цели**. В графике фразы история трафика показывается рядом с ближайшей
   снятой позицией.

Обновление ручное — жми «⟳ Данные» когда нужно освежить (данные всё равно с лагом
~2 дня у GSC и агрегируются за период).
