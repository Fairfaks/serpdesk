# Автообновления SerpDesk

Приложение проверяет обновления через GitHub Releases (electron-updater). Проверка
идёт тихо при запуске и вручную через меню **SerpDesk → Проверить обновления…**
(на Windows: **Справка → Проверить обновления…**).

- На Windows NSIS-сборка скачивает обновление в фоне и предлагает перезапуститься.
- На macOS полная автоустановка требует подписи Apple Developer ID. Пока сборки
  неподписанные, приложение обнаруживает новую версию и предлагает открыть
  страницу скачивания, не загружая заведомо неустанавливаемый ZIP.

Чтобы это заработало, нужен один раз настроить публикацию релизов на GitHub.

## Разовая настройка (для того, кто выпускает сборки)

1. Репозиторий публикации: `Fairfaks/serpdesk`.
2. Для выпуска через GitHub CLI используй токен текущей авторизованной сессии:
   ```bash
   export GH_TOKEN=$(gh auth token)
   ```
3. Выпусти релиз (соберёт dmg/exe и зальёт их + `latest.yml`/`latest-mac.yml` в
   GitHub Releases как черновик):
   ```bash
   export PATH="$HOME/.ScreamingFrogSEOSpider/node/5.1/node/bin:$PATH"
   npm version patch
   npm run publish
   ```
4. Опубликуй созданный черновик:
   ```bash
   gh release edit "v$(node -p "require('./package.json').version")" --draft=false --latest
   ```

Версия в `package.json` должна расти с каждым релизом — по ней идёт сравнение.

## Замечания

- Windows NSIS поддерживает автообновление без сертификата, хотя SmartScreen может
  предупреждать при первом запуске.
- На macOS `electron-updater` использует Squirrel.Mac, который проверяет подпись
  новой версии. Для фоновой установки нужен Apple Developer ID; без него остаётся
  автоматическая проверка и ручное скачивание DMG.
- Приватный репозиторий тоже годится, но тогда у каждого клиента нужен свой доступ —
  для раздачи проще публичный репозиторий только с релизами.
