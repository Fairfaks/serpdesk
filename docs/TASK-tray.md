# Задача: фоновый режим (трей) + автопроверка без окна + системные уведомления

## Что это за проект

SerpDesk — десктопный съёмщик позиций Яндекс/Google (Electron 37, без нативных
модулей). Стек: main-процесс `main.js`, `preload.js` (contextBridge → `window.api`),
рендерер `renderer/{index.html,app.js,styles.css}`, база на sql.js (`lib/db.js`),
логика проверки `lib/checker.js`, клиенты API в `lib/{xmlriver,gsc,yavm}.js`.
Интерфейс на русском, тёмная тема. Node лежит в комплекте Screaming Frog:
`export PATH="$HOME/.ScreamingFrogSEOSpider/node/5.1/node/bin:$PATH"`.

Запуск/сборка:
```bash
export PATH="$HOME/.ScreamingFrogSEOSpider/node/5.1/node/bin:$PATH"
cd serpdesk
npm start            # запуск
npm test             # тесты парсера (должны проходить)
npm run dist:mac     # сборка dmg+zip (arm64)
npm run dist:win     # сборка setup+portable (x64)
```

## Проблема, которую решаем

Автопроверка по расписанию сейчас работает ТОЛЬКО пока открыто окно приложения
(`schedulerTick()` в `main.js` крутится по `setInterval` каждые 30 сек, и при
закрытии окна на не-macOS приложение завершается — см. `app.on('window-all-closed')`).
Нужно, чтобы приложение могло жить в трее/менюбаре и проверять позиции в фоне,
а о результатах сообщать системным уведомлением.

## Что нужно сделать

### 1. Иконка в трее (macOS menubar + Windows tray)

- Создать `Tray` при старте приложения (после `createWindow()` в `app.whenReady`).
- Нужна иконка. Добавь ассеты: `assets/tray/trayTemplate.png` (16×16 и @2x 32×32,
  монохром с альфой — для macOS menubar как Template Image) и `assets/tray/tray.png`
  (цветная 32×32 — для Windows). Сгенерируй простую иконку (буква «S» или простой
  значок графика). На macOS вызвать `tray.setImage` с Template-картинкой (имя файла
  должно оканчиваться на `Template`, тогда menubar сам красит под тему).
- Контекст-меню трея (по-русски):
  - «Открыть SerpDesk» → показать/сфокусировать окно (создать, если закрыто).
  - «Проверить все проекты сейчас» → запустить проверку по всем проектам.
  - разделитель;
  - чекбокс «Автопроверка» (тип `checkbox`, отражает и переключает настройку
    `autocheck_enabled`);
  - строка-статус (disabled): «Последняя проверка: … / Следующая: HH:MM» — обновлять
    текст меню при изменении.
  - разделитель;
  - «Выход» → реальный выход (см. п.2 про флаг).
- Тултип трея: «SerpDesk».
- Клик по иконке трея (`click`/`double-click`) — показать окно.

### 2. Фоновый режим (не закрываться при закрытии окна)

- Новые настройки (добавь в `DEFAULT_SETTINGS` в `main.js`, значения-строки '0'/'1'
  как у существующих): `minimize_to_tray` (по умолчанию '1'), `launch_at_login`
  (по умолчанию '0'), `notify_on_check` (по умолчанию '1').
- Поведение закрытия окна: если `minimize_to_tray === '1'` — при закрытии окна
  (`win.on('close')`) НЕ выходить, а прятать окно (`event.preventDefault()` +
  `win.hide()`; на macOS `app.dock?.hide()` по желанию). Реальный выход — только
  через пункт «Выход» в трее или Cmd/Ctrl+Q: заведи флаг `let quitting = false;`,
  ставь `quitting = true` в обработчике «Выход» и в `app.on('before-quit')`, и в
  `win.on('close')` пропускай, если `quitting`.
- `app.on('window-all-closed')`: если `minimize_to_tray === '1'` — НЕ вызывать
  `app.quit()` (приложение продолжает жить в трее и на Windows тоже). Иначе — как
  сейчас.
- `schedulerTick()` уже крутится на `setInterval` независимо от окна — убедись, что
  он продолжает работать при спрятанном окне (он в main-процессе, так и будет).
  Функция `send()` шлёт в окно только если оно живо — оставь как есть, но результаты
  фоновой проверки должны доходить до пользователя через уведомление (п.3), а не
  только через окно.

### 3. Системные уведомления о результате

- Использовать штатный `Notification` из `electron` (проверять
  `Notification.isSupported()`).
- После завершения проверки проекта (там, где сейчас в `startCheck` шлётся
  `run:done` и вызывается `showVictory()`), если `notify_on_check === '1'` и
  проверка прошла успешно — показать системное уведомление с кратким итогом
  изменений по проекту:
  - Заголовок: `SerpDesk — <имя проекта>`.
  - Тело: сводка дельт последнего прогона против предыдущего, например
    «Вошли в ТОП-3: 2 · Вышли из ТОП-10: 1 · Выпали: 0». Если изменений нет —
    «Позиции без изменений».
  - Отдельно уведомлять об ошибках прогона (`failMessage`) и о фатальных кодах
    (например «На счету XMLRiver закончились деньги»).
- Клик по уведомлению (`notification.on('click')`) — показать окно и открыть этот
  проект (можно послать в рендерер IPC-событие `focus:project` с `projectId`, а в
  `renderer/app.js` подписаться и переключить `S.activeId` + `render()`).
- Реализуй в `main.js` функцию сводки дельт, напр. `summarizeDeltas(projectId, engine)`:
  взять два последних НЕ-running прогона этого проекта/движка из таблицы `runs`,
  сравнить `results` по фразам и посчитать: вошли в ТОП-3, вышли из ТОП-10, выпали
  из ТОП (было >0, стало 0), вернулись. Логику сравнения можно подсмотреть в
  `renderer/app.js` → `compareRuns()` (там аналогичное на стороне рендерера).
- Уведомления слать при ЛЮБОЙ автопроверке (фоновой и при открытом окне); при ручной
  проверке из окна — не обязательно (окно и так покажет тост). Ориентир: помечай
  фоновые прогоны или просто всегда шли уведомление, если `notify_on_check==='1'`.

### 4. Автозапуск при входе в систему

- Настройка `launch_at_login`. При её изменении и при старте применять:
  `app.setLoginItemSettings({ openAtLogin: <bool>, openAsHidden: true })`
  (кроссплатформенно, работает на macOS и Windows).

### 5. UI в настройках (`renderer/app.js`, модалка настроек)

Рядом с блоком автопроверки добавить три чекбокса (стиль — как существующий
`label.check`): «Сворачивать в трей вместо выхода» (`minimize_to_tray`),
«Запускать при входе в систему» (`launch_at_login`), «Уведомлять о результатах
проверки» (`notify_on_check`). Значения читать/писать через `window.api.getSettings`
/`setSettings` (сохранение уже идёт объектом в обработчике «Сохранить» —
добавь туда новые ключи). Если добавляешь применение автозапуска — прокинь
IPC-хэндлер (напр. `h('app:apply-login-item', ...)`), вызывай после сохранения.

## Технические требования и стиль

- Electron 37, только встроенные API (`Tray`, `Menu`, `Notification`,
  `nativeImage`, `app.setLoginItemSettings`) — НИКАКИХ новых npm-зависимостей.
- Кроссплатформенно: должно работать и на macOS (menubar), и на Windows (tray).
- Держи текущий стиль кода: русские комментарии, IPC через хелпер `h(name, fn)`
  внутри `registerIpc()`, настройки строками '0'/'1', preload — добавляй методы в
  `contextBridge` и новые каналы в whitelist массива `allowed` в `preload.js`.
- Не ломай single-instance lock, существующую автопроверку, видео-финал
  (`showVictory`) и уже добавленный `initUpdater`.
- Подними версию в `package.json` (сейчас 1.3.0 → 1.4.0).
- В `package.json` → `build` добавь ассеты трея в `files`, если их там ещё нет
  (уже включён `assets/**`).

## Как проверить (обязательно)

1. `node --check main.js && node --check preload.js && node --check renderer/app.js`
   — без ошибок; `npm test` — проходит.
2. `npm start`, в настройках включить «Сворачивать в трей». Закрыть окно — процесс
   приложения ЖИВ, иконка в трее есть, «Открыть SerpDesk» из меню трея снова
   показывает окно.
3. Включить автопроверку с временем через 1–2 минуты, закрыть окно, дождаться —
   проверка проходит в фоне, появляется системное уведомление с корректной сводкой;
   клик по нему открывает окно на нужном проекте.
4. Тумблер «Запускать при входе» реально меняет `app.getLoginItemSettings().openAtLogin`.
5. `npm run dist:mac` и `npm run dist:win` собираются без ошибок.
